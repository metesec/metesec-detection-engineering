# MeteSec Detection Pack v1.0.0

Version 1 establishes the first complete, bounded Detection Pack: one stable
logical identity and one authored Sigma implementation per detection, with
Microsoft Sentinel as the only supported target.

## Included

- fifty experimental Sigma detections with stable IDs `MSEC-DET-0001`
  through `MSEC-DET-0050`;
- one hundred fifty positive and two hundred negative flat synthetic fixture
  cases for the repository's deliberately bounded local evaluator;
- deterministic machine-readable and human-readable catalogues;
- forty-nine explicit Microsoft Sentinel preview bindings and forty-nine
  reviewed Golden KQL snapshots across five governed Sentinel data sources;
- a versioned analytics-rule profile that governs repository rendering of
  forty-nine deterministic, disabled Scheduled-rule request bodies in the
  consumer's own pipeline;
- generated coverage recording sixty-nine ATT&CK mappings across thirty-nine
  techniques and eleven tactics, without an invented completeness score;
- lifecycle, data-source-health and rule-runtime-health contracts;
- an internal manifest containing the normalized size and SHA-256 digest of
  every packaged source.

## Important boundaries

- All fifty detections remain `experimental`. The `1.0.0` version identifies a
  complete project and pack contract, not production-ready detection logic.
- `MSEC-DET-0001` keeps its original Sentinel target intent but has no preview
  binding because the verified target has no suitable Windows event telemetry.
  A declared implementation target is not a target-support claim without an
  explicit preview binding.
- Sigma is the only authored detection format in version 1. Generated KQL is a
  reviewed target projection, not a second authored rule.
- The Sentinel output contract is version 2. Consumers of the earlier preview
  must review the current output columns and entity mappings before adoption.
- The archive contains no prebuilt Sentinel target bundle, Azure resource
  scope, credential, deployment client, live telemetry, runtime observation,
  customer exception, allowlist or tuning overlay.
- Synthetic matches, successful compilation and bounded live query acceptance
  do not establish malicious activity, target performance or production
  approval. Consumers must validate and tune the rules in their own environment.

## Integrity verification

Download the ZIP and `SHA256SUMS` into the same directory, then run:

```console
sha256sum --check SHA256SUMS
```

The expected result is `metesec-detection-pack-v1.0.0.zip: OK`. The checksum
verifies the downloaded bytes; it does not prove authorship. The ZIP's
`RELEASE-MANIFEST.json` provides a second per-file integrity inventory.
